# سامانهٔ محلی برای بررسی Flow

این نسخه یک برش اجرایی محلی است؛ جایگزین production نیست. با Python استاندارد ویندوز اجرا می‌شود و به Docker، دیتابیس بیرونی یا نصب package نیاز ندارد.

## اجرا

از پوشهٔ `cutover` در PowerShell:

```powershell
.\run-local.ps1
```

یا `py -3 -m application` و سپس مرورگر در `http://127.0.0.1:8765` باز می‌شود. برای توقف، در پنجرهٔ PowerShell `Ctrl+C` بزنید.

پایگاه‌داده در `application/data/cutover.sqlite3` ایجاد می‌شود؛ فایل در Git ثبت نمی‌شود. برای شروع پاک، وقتی برنامه بسته است همین فایل را حذف کنید. `CUTOVER_DB` امکان تعیین مسیر دیگر را می‌دهد.

## بخش‌های قابل آزمون

- رکورد مشترک روتر و درخواست‌های جداگانهٔ QA، TEMP، ATP و Handover.
- صف عملیات، Claim، تأیید و برگشت برای اصلاح؛ پروژه می‌تواند درخواست برگشتی را دوباره ارسال کند.
- TEMP را می‌توان Claim کرد و بررسی نمود، ولی تأیید تا پایان دورهٔ مشاهده مسدود است.
- برنامهٔ Cutover هفتگی قابل ساختن پیش از تکمیل آمادگی است؛ مجری برنامه اختیاری، مجری واقعی هنگام ثبت نتیجه مستقل است.
- شروع Cutover موفق تا تأیید QA، TEMP و ATP معتبر مسدود است. ATP منقضی/ناموجود برای آن ردیف یک تمدید ATP در صف می‌سازد.
- Handover بر اساس زمان اجرای موفق Cutover و فاصلهٔ تنظیم‌شده قابل ثبت می‌شود.
- تنظیم زمان‌ها برای تسریع سناریو در محیط آزمایشی وجود دارد.

نمونه‌های اولیه ساختگی‌اند. انتخاب نقش فقط شبیه‌سازی رابط است و احراز هویت یا کنترل دسترسی امنیتی ایجاد نمی‌کند. اعتبار ATP برابر ۳۰ روز صرفاً مقدار پیش‌فرض آزمایشی این برش است، چون مقدار تولیدی هنوز تعیین نشده است.

## مرز معماری

`workflow.py` قواعد فرایند را از HTTP و `store.py` جدا نگه می‌دارد؛ `store.py` آداپتر SQLite محلی است. این مرز کمک می‌کند بعداً آداپتر پایگاه‌داده و میزبان RHEL تغییر کند، در حالی‌که Flow و قراردادهای دامنه تا حد ممکن باقی بمانند. هنوز تصمیم یا پیاده‌سازی production برای PostgreSQL، احراز هویت، مجوزها، مهاجرت‌ها، پشتیبان‌گیری و بسته‌بندی انجام نشده است.
